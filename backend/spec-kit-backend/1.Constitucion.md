# Constitución del backend del refugio de animales

## 1. Objetivo

Construir una API REST para autenticar al administrador y gestionar animales almacenados en PostgreSQL.

## 2. Tecnologías

- TypeScript y Node.js.
- Hono.js para la capa HTTP.
- PostgreSQL mediante `pg`.
- JWT mediante `jose`.
- `bcrypt` con 8 rondas para contraseñas.
- Zod para validación.
- Variables de entorno mediante `.env`.

## 3. Arquitectura

Se utiliza una arquitectura de tres capas:

1. **HTTP / Presentación:** rutas, controladores, middlewares y esquemas Zod.
2. **Servicios / Lógica de negocio:** casos de uso y reglas de aplicación.
3. **Persistencia:** repositorios y consultas parametrizadas hacia PostgreSQL.

## 5. Entidades

### Administrador

`Identificador`, `Usuario`, `Contrasena`.

El usuario tendrá una longitud máxima de 15 caracteres. La contraseña se almacenará como hash bcrypt con 8 rondas y una longitud máxima de 60 caracteres.

### Animal

`Identificador`, `Nombre`, `Raza`, `Edad`, `Sexo`, `FechaIngreso`, `TipoAnimal`.

`Sexo` acepta `Hembra` o `Macho`; `TipoAnimal` acepta `Perro` o `Gato`. `FechaIngreso` utiliza `CURRENT_DATE` en PostgreSQL.

## 6. Requerimientos funcionales

1. Iniciar sesión como administrador.
2. Cerrar sesión eliminando el JWT del cliente.
3. Registrar animales.
4. Actualizar animales.
5. Listar animales.
6. Listar animales con filtros combinables por nombre, raza, sexo y tipo de animal.

No se implementará eliminación de animales.

## 7. Endpoints

| Método | Ruta | Autenticación |
|---|---|---|
| POST | `/auth/login` | No |
| POST | `/auth/logout` | Sí |
| POST | `/animals` | Sí |
| PUT | `/animals/:id` | Sí |
| GET | `/animals` | Sí |

Los filtros de `GET /animals` son opcionales: `nombre`, `raza`, `sexo` y `tipoAnimal`.

## 8. Autenticación

El inicio de sesión valida usuario y contraseña con Zod y bcrypt, y devuelve un JWT firmado con `jose`. Las rutas protegidas requieren `Authorization: Bearer <token>`. El logout es stateless: el backend confirma la operación y el cliente elimina el token. No se almacenan tokens revocados.

Credenciales iniciales: `chacaeadm` / `chacaeadm123`. En la base de datos debe almacenarse el hash bcrypt, nunca la contraseña en texto plano.

## 9. Variables de entorno

```env
PORT=3000
DATABASE_URL=postgresql://usuario:contrasena@localhost:5432/refugiodb
JWT_SECRET=clave-secreta
JWT_EXPIRES_IN=1h
BCRYPT_ROUNDS=8
```

## 10. Fases

1. Especificación e inicialización de TypeScript y Hono.
2. Configuración de PostgreSQL y repositorios.
3. Validaciones con Zod.
4. Seguridad con bcrypt y JWT.
5. Autenticación y logout.
6. CRUD parcial de animales: registrar, actualizar y listar.
7. Filtros combinables y manejo de errores.
8. Integración final y verificación de criterios de aceptación.

## 11. Criterios de aceptación

- La aplicación inicia y responde mediante Hono.
- Se conecta a `refugiodb`.
- El administrador puede iniciar sesión con las credenciales iniciales.
- La contraseña se compara mediante bcrypt con 8 rondas.
- Las rutas de animales requieren JWT.
- Se pueden registrar, actualizar, listar y filtrar animales.
- Las entradas inválidas son rechazadas por Zod.
- PostgreSQL genera `FechaIngreso` automáticamente.
